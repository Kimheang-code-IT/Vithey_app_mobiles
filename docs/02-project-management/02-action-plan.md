## 1. How to read this plan

This table restates `Action_Plan_Vithey.csv` in the bank-reporting column format. Read the
following provenance rules before using any cell.

- **Source of truth for rows, status and progress:** the untracked `Action_Plan_Vithey.csv`.
  Those statuses/progress values are the action-plan author's reported figures. They are **not
  independently verified** in this documentation task. Where a repository artefact corroborates a
  deliverable, that is stated in *Completion Evidence*; where it cannot be corroborated, it is marked
  accordingly.
- **Dates** shown in *Start Date* / *End Date* are **evidence-derived** from git activity windows
  (the CSV's own remarks say the dates are "the git activity window"). They are **not contractual
  planned dates**. Blank/unknown dates are `TBD`.
- **Responsible Person** names are `[INFERRED]` from `Action_Plan_Vithey.csv` / git author metadata
  where a name appears; `TBD` where unknown. Inferred from implementation — requires business confirmation.
- **Scope Classification** is `[INFERRED]` from `plan.md` §0/§8 (locked demo scope) and the delivered
  module set — requires business confirmation. Legend:
  - **Original Scope** — part of the locked Profile M demo scope.
  - **Additional Work** — evidenced as added beyond the initial service baseline (notably `map-service`).
  - **Future Enhancement** — explicitly out of the demo scope or a post-demo governance activity.
  - **Internal Technical Improvement** — defect fix / hardening / internal correction.
  - **TBD** — scope genuinely unclear.
- **No overall contractual completion percentage is computed here from Future Enhancement or
  Internal Technical Improvement tasks.** Per-instance progress is copied from the CSV only.
- **Test-related claims are not "passed".** `EVIDENCE-BASIS.md` §10 states test execution was not
  performed during documentation. Test artefacts exist; results are not independently verified.
